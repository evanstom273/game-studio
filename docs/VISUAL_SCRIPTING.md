# Visual scripting

Blueprint-style scripts: wire nodes together instead of writing TypeScript. A visual script is a
`.vgraph` file in the project; you attach it to a node exactly like a code script.

## How it works

```
scripts/player.vgraph  ──compile──▶  TypeScript  ──esbuild──▶  game.js
 (graph, JSON)          @gs/visual    export default class      (same as code scripts)
                                      Player extends …
```

- The graph packages come from Coding Studio (`packages/visual/*`, imported as `@cs/*`): the
  graph model, type system, IR, node registry, compiler pipeline, the TypeScript printer and the
  atomic edit operations. They are copies; Game Studio-specific changes are marked in the files
  (the printer can emit `export default class`, `static exports` and signal fields).
- `packages/visual/gamestudio` (`@gs/visual`) is the Game Studio "language" on top: the adapter,
  types (the engine's class hierarchy) and the node pack.
- Before the game runs or is exported, every `.vgraph` is compiled to TypeScript
  (`expandVisualScripts`, called from `apps/editor/src/scripting/compiler.ts`). The generated code
  is an ordinary engine script, so exports, signals and the inspector work the same for both kinds.
  Graph errors are reported per file in the console, like compile errors.

A script graph has:

- **Settings** — the node type it is for (`extends`, e.g. `CharacterBody2D`). Its properties and
  functions act on "self" when a node's target pin is left unconnected.
- **Events** — Ready (`_ready`), Every Frame (`_process`), Every Physics Tick (`_physicsProcess`),
  On Input (`_input`), Enter Tree, Exit Tree. Each is a graph.
- **Functions** — your own graphs with parameters and a return value.
- **Variables** — fields of the script. Tick *exported* to edit them in the Inspector.
- **Signals** — your own signals (`Emit Signal`); other scripts connect to them.

## The nodes

Generated from the engine, so new node types get nodes automatically:

| Category | What's in it |
|---|---|
| `Nodes/<Type>` | Get/Set for every property of every node type, and its methods (e.g. Move And Slide, Is On Floor, Play, Start) |
| `Input` | Is Action Pressed / Just Pressed / Released, Get Vector, Get Axis, keys, pointer, touches |
| `Signals` | Connect Signal (with "On Body Entered (Area2D)"-style presets for every engine signal), Emit Signal, Wait For Signal |
| `Scene` | Get Node (with a type), Spawn Scene, Instantiate Scene, change/reload scene, groups, pause, quit |
| `Math/Vector2`, `Math/Vector3`, `Math/Color` | Make/Break, Add/Subtract/Scale, length, normalized, distance, lerp, rotate… |
| `Time` | Wait (seconds) — the function carries on later, the game keeps running |
| `Tween`, `Resources` | tweening properties, loading textures/sounds/scenes |
| Flow, Math, Logic, Strings, Arrays, Dictionaries, Variables, Debug… | Coding Studio's core nodes (Branch, loops, Switch, Sequence, Print…) |

The engine part is built in `packages/visual/gamestudio/src/api.ts` from the node registry's
properties and the script editor's API catalogue (`packages/scripting/src/api.ts`); untyped
parameters there get a type from their name (`action` → string, `seconds` → float…).

## Generated code

```ts
// Generated by Game Studio from the visual script "Player".
import { CharacterBody2D, Input } from 'gamestudio';

export default class Player extends CharacterBody2D {
	static exports = ['speed'];
	speed: number = 200;

	_physicsProcess(delta: number): void {
		this.velocity = Input.getVector('ui_left', 'ui_right', 'ui_up', 'ui_down').scale(this.speed);
		this.moveAndSlide();
	}
}
```

Functions that use Wait / Wait For Signal become `async` automatically.

## For AI assistants (MCP)

`list_visual_nodes`, `get_visual_node`, `get_visual_script`, `create_visual_script` and
`edit_visual_script` work on the cloud copy, so Game Studio doesn't have to be open. Edits use
Coding Studio's atomic operations (`add_node`, `connect`, `add_variable`, `add_function`…), are
one undo step, and appear live in an open editor. The AI is told to change visual scripts only
through these tools, never by rewriting their JSON.

## Checks

The compiler explains problems in plain terms, for example: a variable called `position` on a
Node2D script ("already part of Node2D"), a CharacterBody2D node used in a Node2D script without
a target, a Connect Signal without a function, a wrong pin type.

## Tests

`tests/unit/visual.test.ts` builds graphs, compiles them, bundles them with esbuild and runs them
in the engine (the compiled player actually moves). `tests/unit/cloud.test.ts` drives the MCP
tools the way an AI would.
